# TL00 — One Game, Two Runtimes

**CLOSED — accepted and merged to `main` on October 12, 2026.**

## Objective and scope

Demonstrate that **one checked-in Godot 3D sample** can be built, replayed, inspected and compared on exported **Web and Android runtimes** without editor interaction. For TL00, a GitHub-hosted Android emulator is an authorized Android runtime.

**TL00 is an automated portability/QA infrastructure acceptance gate, not certification of an Android hardware class or production-game performance.** No physical smartphone is required to close TL00.

### TL00-R3 — Automated telemetry and reproducible evidence
**CLOSED — actual exported runtime and acceptance CI PASS** — engine-observed FPS, process and physics timings, static memory, Android API/model/renderer/emulator flag, APK SHA-256 and canonical replay SHA-256 are emitted. The report includes images, spatial differences, and **observational** performance metrics. CI measurements are not evaluated against physical mobile FPS targets.

TL00-R3 closure evidence: [PR #1 exact-head CI #38216200326](https://github.com/ictseoyoungmin/talarion/actions/runs/38216200326) passed every Node, Web, Android and parity job, including nine machine-readable acceptance checks and telemetry/provenance validation. Emulator FPS remains observational rather than phone performance certification.

### TL00 acceptance contract

`node bin/talarion.mjs gate tl00 <web-dir> <android-dir> <visual-result.json> <out.json> --json`

The command rejects incomplete or mismatched runner evidence, missing replay/ APK hashes, fewer than 15 authoritative state snapshots, failed visual checkpoints, missing engine performance telemetry, and unknown Android device kind. The GitHub Actions pipeline runs the gate after Web/Android replay and visual comparison. [PR #1](https://github.com/ictseoyoungmin/talarion/pull/1) merged into `main` at `8dbf1754a390db0459eef558845e653ef1501bd5` after its acceptance CI passed. The machine-readable result schema is `talarion.tl00-acceptance/v1`, and `hardwareCertified` is **always false**.

The following conditions were verified before TL00 was CLOSED and merged into `main`:
1. Node 20/22/24 test/verify jobs pass;
2. exported Web and Android runtime jobs pass using the canonical checked-in replay;
3. 15/15 state and all three visual checkpoints pass their **unchanged** tolerances;
4. replay fingerprints match, evidence manifests include valid Android identity and APK fingerprint;
5. performance samples are present and valid, reported as observations only;
6. the TL00 acceptance JSON, HTML report and Web/Android screenshot/difference evidence are uploaded; and
7. the reviewed PR head passes its required GitHub CI.

## Non-goals and limitations

- Android CI currently uses AOSP API 30 with `-gpu swangle` to avoid documented Android 35 launcher/virtual-GPU failures.
- TL00 does not prove performance, graphics compatibility, thermal stability, accessibility or lifecycle behavior on **physical devices**.
- TL00 does not certify arbitrary game projects, all Godot renderer/device combinations, Android 35, or iOS.
- The UI and underlying image-comparison algorithms may evolve independently after TL00 closure; reopen on a substantive QA regression.

See [Release Certification](release-certification.md) for separately qualified hardware/device claims and [TL02](roadmap.md) for budget modeling. The physical gate is intentionally not a blocker on TL00 development or merge.
