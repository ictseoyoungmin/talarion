# TL00 — One Game, Two Runtimes

## Goal

Prove the core architecture using one small Godot 3D game and two runtimes:

- Web
- Android

The same checked-in replay must execute in both and produce comparable evidence.

## Slice status

### TL00-R1 — Runtime state parity

**CLOSED**

Gate evidence:

- one checked-in 600-tick replay executes in exported Web and Android builds;
- both runtimes finish at tick 600;
- both emit the same authoritative state schema;
- CI compares 15 checkpoint/interval snapshots;
- 15/15 snapshots match;
- state parity is 100.00%.

### TL00-R2 — Visual parity

**CLOSED**

CI evidence: [TL00-R2 spatial gate PASS](https://github.com/ictseoyoungmin/talarion/actions/runs/37957078215), commit `7c7f0351076c`.

- exported Godot Web and Android 11 (API 30) AOSP builds run the same canonical replay;
- 15/15 authoritative state snapshots matched;
- Web and Android screenshots agree on `after-jump`, `interaction`, and `attack`;
- 3/3 images pass global RGB and 16×9 regional tile error gates;
- average visual similarity: 99.9759%; worst regional tile ≤1.151% vs 2% threshold;
- visual artifacts contain both normalized captures, difference PNGs, and an HTML QA board;
- regression guard rejects blank frames, wrong capture ticks, and localized differences masked by the average;
- Godot capture hold was extended to protect Android ADB screenshot timing;
- CI uses Android 30 AOSP with ANGLE-backed SwiftShader (`-gpu swangle`) because earlier Android 35 launcher failures and legacy GPU modes invalidated evidence.

These results establish the **minimal TL00 sample**, not general-game portability, Android 35 support, mobile performance, or physical-device certification.

### TL00-R3 — Device performance and physical-device gate

**ACTIVE — instrumentation implemented, physical-device gate OPEN**

Both runners now record engine-observed FPS, frame/process time, and static memory counters as `performance.jsonl` and `talarion.performance/v1` summaries. The CI emulator provides useful diagnostics but **does not certify frame-rate budgets**; CI virtualized GPU measurements differ from physical devices.

Next: validate performance report evidence and execute the same canonical replay on a physical Android device. Capture hardware identity, GPU, build revision, screenshots, performance distributions, and target-budget decisions. TL00 stays OPEN until this gate passes.

## TL00 closure criteria

TL00 is closed only when all of the following hold:

1. one checked-in replay executes in an exported Web build and a real Android build;
2. both runtimes emit authoritative state using the same evidence schema;
3. configured state remains within declared tolerance;
4. named visual checkpoints are captured and compared;
5. build/replay/compare/report can run without editor interaction;
6. at least one physical Android device passes the gate;
7. failure reports contain enough evidence to reproduce the divergence.

R1 closure does not close TL00.
