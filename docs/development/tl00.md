# TL00 — One Game, Two Runtimes

## Goal

Prove the core architecture using one small Godot 3D game and two runtimes:

- Web
- Android

The same checked-in replay must execute in both and produce comparable evidence.

- [x] CLI and configuration surface
- [x] project/config discovery
- [x] Godot executable detection
- [x] Godot Web/Android build orchestration
- [x] portability doctor baseline
- [x] replay schema and validator
- [x] state snapshot JSONL format
- [x] state comparator with tolerance
- [x] HTML parity report

## Open runtime gates

- [ ] Web runner launches the exported game in an automated browser
- [ ] Web runner collects state evidence
- [ ] Web screenshot checkpoints
- [ ] ADB Android install/launch runner
- [ ] Android state evidence collection
- [ ] Android screenshot checkpoints
- [ ] visual comparison metric
- [ ] device performance telemetry
- [ ] `talarion test web`
- [ ] `talarion test android`
- [ ] physical Android-device validation

## Closure criteria

TL00 is closed only when all of the following hold:

1. one checked-in replay executes in an exported Web build and a real Android build;
2. both runtimes emit authoritative state using the same evidence schema;
3. configured state remains within declared tolerance;
4. named visual checkpoints are captured and compared;
5. build/replay/compare/report can run without editor interaction;
6. at least one physical Android device passes the gate;
7. failure reports contain enough evidence to reproduce the divergence.

Fixture parity and structural bridge checks alone do not close TL00.
