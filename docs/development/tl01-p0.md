# TL01-P0 — Portability Doctor Diagnostic Contract

**Development scope:** reusable source rule catalog, stable finding identity, deterministic file/line/column evidence, and fixture-backed positive/negative tests. This is not a claim that Talarion has implemented storage/haptics platform adapters.

## Diagnostic schema

Doctor emits **talarion.doctor/v1** with:

- ok (false only if any error exists), errors, warnings, infos;
- checks (all project/toolchain checks plus source rule occurrences, including pass);
- diagnostics (only actionable non-pass findings);
- rulesEvaluated (stable catalog IDs).

Each finding includes id (PFnnn), severity, category, capability, targets, message, remediation, optional repo-relative POSIX file and **1-based** line/column. A warning does not fail Doctor; an error does. These are detection contracts, not proof of target support.

| Prefix | Class | Use |
| --- | --- | --- |
| PF0xx | foundation | project/toolchain/presets |
| PF1xx | code-api | browser APIs or direct gameplay input |
| PF2xx | asset-budget | static assets/profile constraints (future) |
| PF3xx | renderer | shaders/graphics capabilities (future) |
| PF4xx | lifecycle-input-storage | lifecycle/platform adapters (future) |
| PF5xx | build-export | target export constraints (future) |
| PF6xx | replay-parity | cross-runtime evidence assumptions (future) |

Current rules: PF001 missing project **error**; PF002 missing export presets **warning**; PF003 missing Godot executable **warning**; PF102 localStorage Android warning; PF103 navigator.vibrate Android warning; PF104 Godot raw-key polling warning.

## Source scanning boundaries

- Recognizes .gd, .js, .mjs, .ts inside the configured Godot project.
- Walks files deterministically, excluding generated .godot, .import, .git, .talarion, artifacts, build, dist, node_modules and symlinks.
- Masks line/block comments and quoted literals before applying the catalog patterns, preserving offsets and newlines. GDScript triple-quoted strings are masked as well.
- This is **conservative lexical detection**, not an AST parser. It can miss computed property access, embedded JS template expressions and dynamically generated code, or report similarly named non-platform symbols. These semantic refinements belong to TL01-P1.
- Findings preserve exact source locations and remediations without embedding raw source lines.

## Reproduction

Run the CLI doctor with --json to inspect diagnostics. Run npm test for the Node fixture coverage. CI still executes the entire exported Web/Android replay, visual parity and TL00 acceptance tests; P0 does not change runtime QA tolerances.

## Closure boundary

P0 closes after PR-head CI verifies catalog integrity, warning/error semantics, fixture tests, stable source coordinates, deterministic ordering and no TL00 regression. TL01-P1 may then extend detector coverage without breaking existing rule IDs.
