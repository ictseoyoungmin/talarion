# TL01-P1 — Target Boundary and Adapter Diagnostics

TL01-P1 extends the stable talarion.doctor/v1 diagnostics established in [P0](tl01-p0.md). This is a static portability audit, not a claim that Talarion has implemented gameplay platform adapters.

## Added rule IDs

| Rule | Affected target | Signal |
| --- | --- | --- |
| PF105 | Android | Browser sessionStorage |
| PF106 | Android | Godot JavaScriptBridge browser-only calls |
| PF107 | Web | Godot JavaClassWrapper Android JNI access |
| PF108 | Web | Engine.get_singleton("AndroidRuntime") |
| PF109 | Android | Direct browser AudioContext construction |
| PF401 | Android | Browser page lifecycle events and visibility properties |
| PF402 | Android | Browser keyboard DOM event registration |
| PF403 | Web / Android | Direct Godot physical-key polling |
| PF404 | Web | Godot OS.execute subprocess |
| PF405 | Target-specific | Required adapter missing or declaration invalid |

Existing PF001–PF104 IDs, severity and report shape are preserved. PF104/PF403 recommend action mapping and do not, by themselves, require a platform adapter.

The lifecycle rule covers pagehide, pageshow, beforeunload, visibilitychange, freeze, resume and common document visibility flags. The input rule covers keydown, keyup and keypress. Direct window/document addEventListener calls must have a quoted first argument to be recognized as a known event; computed event names remain unknown rather than certified portable.

Godot target restrictions follow the upstream documentation: [JavaScriptBridge is Web-only](https://docs.godotengine.org/en/stable/classes/class_javascriptbridge.html), while [JavaClassWrapper is Android-only](https://docs.godotengine.org/en/stable/classes/class_javaclasswrapper.html).

## Optional adapter declarations

Target-specific API use in the canonical gameplay sources produces the relevant API diagnostic and checks the declared target adapter boundary. The optional talarion.config.json shape is:

    "portability": {
      "adapters": {
        "platform.storage": {
          "android": "examples/ruins-lite/adapters/android/storage.gd"
        },
        "platform.lifecycle": {
          "web": "examples/ruins-lite/adapters/web/lifecycle.gd"
        }
      }
    }

Paths are relative to repository root and must point to existing source files under the configured Godot project's adapters/<target>/ directory. Nonexistent files, escaping paths, wrong target folders and files resolving outside the project do not satisfy this contract. PF405 reports the missing or invalid capability and target.

A declared source file is not a runtime implementation certificate. A legitimate Android adapter may call Android JNI without producing a Web warning, but a Web adapter calling Android JNI still triggers a warning. Canonical gameplay files never receive adapter exemptions.

## Conservative limits

- Warnings are review signals: a clean Doctor result does not prove that a game runs correctly on all targets.
- Lexical checks cannot prove aliases, target guards, dynamic event strings or generated code portable. Directly guarded target API calls may be valid but still deserve boundary review.
- The adapter contract confirms source path and intended ownership, not functional behavior, state parity, thermal safety or device FPS.
- PF405 only applies to target-only dependencies requiring an equivalent adapter or fallback; action-map advice does not require adapter file declarations.
- TL00's exported Web/Android replay, state, screenshot, spatial tile and telemetry gates remain unchanged.

## Reproduction and acceptance

Run the CLI Doctor with --json to inspect findings and npm test for fixture-backed positive/negative detection. CI must continue to pass Node 20/22/24 and all exported Web/Android TL00 acceptance jobs.
