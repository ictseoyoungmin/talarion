# TL02-P0 — Runtime Performance Evidence Authority

P0 establishes an **evidence-provenance contract**. It does not claim target FPS compliance, device performance, draw-call counts or thermal certification.

## Input and CLI

The command reads **actual exported runner artifacts**, not checked-in sample fixtures:

    node bin/talarion.mjs budget authority \
      artifacts/run/web artifacts/run/android artifacts/parity/performance-authority.json --json

Inputs for each target:
- \`runner-result.json\`: \`talarion.runner-result/v1\`, target, completion status, engine performance summary and replay hash; Android APK hash and device/emulator identity, or a known headless Web browser.
- \`performance.jsonl\`: raw, ordered engine-observed samples.
- \`talarion.config.json\`: target profile's *declared* target FPS and draw-call budget, not measurement outcomes.
- Canonical replay file: independently recomputed SHA-256.

The authority validator requires a valid runner manifest, matching replay provenance, known runtime class, at least three valid ordered telemetry samples, a SHA-256 hash of the raw sample bytes, and **exact reproduction** of the runner's FPS quantiles, frame/physics timing, memory peak, sample count and declared-FPS field.

## Machine-readable output

The versioned output \`talarion.performance-authority/v1\` contains a per-target set of six checks (PA01–PA06) with explicit error visibility, as well as:

| Field | Meaning |
| --- | --- |
| \`declared.targetFps\` / \`drawCallBudget\` | Configuration goal only; not observed |
| \`runtimeKind\` | \`headless-browser\`, \`android-emulator\`, \`android-physical-unreviewed\` or \`unknown-*\` |
| \`observation.status\` | \`validated-runner-observation\` only after checks pass; otherwise \`unverified\` |
| \`observation.metrics\` | Recomputed FPS P10/median, process and physics P95, peak engine-reported memory |
| \`observation.sampleSha256\` | Content fingerprint of raw performance JSONL |
| \`observation.unobserved\` | Draw calls, texture GPU memory and thermal headroom remain explicitly unavailable |
| \`budgetDecision\` | Always \`not-evaluated\` in P0 |
| \`certification\` | Device, target FPS, draw-call and thermal certification all remain false |

An invalid runner or a missing sample cannot produce a validated result. The command writes an actionable failure artifact and exits nonzero when the contract fails. Declared targets are not threshold-tested in P0; metric units, actual budget policy and statistical regression gates belong to subsequent TL02 slices.

## Trust boundary

A self-reported JSON manifest is not independent hardware attestation. P0 cross-checks the runner summary against the actual sample files and the local canonical replay hash. Its validation is meaningful within the *trusted CI execution and artifact-chain* and should not be represented as proof against a malicious generator capable of fabricating the entire JSONL/runner file pair.

An Android manifest with \`isEmulator: false\` is classified **physical-unreviewed**, never certified. Real device release claims require the separate [Release Certification](release-certification.md) including reviewed lifecycle, thermal and compatibility measurements.
