# TL03-P0 — iOS Host and Export Evidence Authority

TL03-P0 added a host/toolchain **preflight** for a future iOS target. The later TL03-P1 Xcode ZIP export implementation has been merged, but **iOS is now deferred**. P0 alone is not an iOS exporter, signed app, simulator runner or parity certification. No native macOS/Xcode ZIP export evidence has been independently verified.

## Proven platform constraints

Godot 4.7 iOS export requires **macOS + Xcode + installed matching Godot export templates**. Godot exports an Xcode project; iOS builds, provisioning and signing are performed through the Apple toolchain. The iOS Simulator supports only the Godot **Compatibility** renderer (the project's mobile rendering method takes precedence). The iOS export requires an App Store Team ID and a bundle identifier. See the [Godot 4.7 iOS exporter manual](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_ios.html).

Linux CI can inspect and validate source/project settings, but cannot claim a signed iOS build or a simulator/device runtime result. Web/Android evidence must **not** be used as an iOS runtime proxy.

## CLI

```bash
node bin/talarion.mjs ios preflight artifacts/ios/ios-preflight.json --json
```

The deterministic schema is `talarion.ios-preflight/v1` with eleven explicit checks:

| Check | Required authority |
| --- | --- |
| IOS-01 | macOS host |
| IOS-02 | Xcode installed and `xcode-select` selects full Xcode |
| IOS-03/04 | iPhoneOS and iPhoneSimulator SDKs observed through `xcrun` |
| IOS-05 | Godot executable available |
| IOS-06 | **actual** Godot project preset named iOS, platform iOS |
| IOS-07 | well-formed reverse-DNS bundle identifier |
| IOS-08 | valid App Store Team ID syntax |
| IOS-09 | configured Godot mobile renderer compatible with iOS Simulator |
| IOS-10 | matching Godot iOS export templates — **unverified in P0** |
| IOS-11 | signing, provisioning and produced Xcode archive — **unverified in P0** |

The preflight's `ok=true` means only **the audit command executed**. For an unprepared Linux runner it reports `status=blocked`; when all nine inspectable prerequisites are detected on macOS it reports `status=prerequisites-detected`. Neither status changes `exportReady=false`, `exportAttempted=false`, `appSigned=false`, or any runtime/certification boolean. IOS-10/11 remain **unverified** until independent P1/P2 evidence exists.

`talarion.config.json` defines a nonsecret sample bundle identifier, a future preset name and `appStoreTeamId=null` intentionally. An actual Apple Team ID, provisioned signing identity and iOS preset must be supplied by the rightful app developer; never embed signing credentials, fake an ID or silently default to simulator success. No iOS keychain or signing secrets are read or exported by P0.

## CI and QA

Since TL03 was deferred, regular CI **does not execute/upload a standalone iOS preflight**. `npm test` still runs TL03-P0/P1 negative contract tests on the supported Node matrix, preserving fail-closed Linux behavior without extra iOS-specific artifacts. The optional manual `talarion ios preflight` command remains available; it cannot certify export or runtime.

Negative tests cover Linux/Windows even with spoofed tool flags; missing Xcode/iOS SDK/Godot; missing/mislabelled iOS preset; invalid bundle/Team ID; mobile renderer override; path escape and output symlink. Positive mock macOS tests reach only `prerequisites-detected`, never exported/signature certified.

The original Web/Android CI still enforces TL00 **15/15 state, 3/3 spatial visual checkpoints, 9/9 acceptance**, and TL02 source-verified observational budgets. Intermittent screenshot [QA issue #4](https://github.com/ictseoyoungmin/talarion/issues/4) and physical-device [Release Certification](release-certification.md) remain separate.

## Status and resumption

**TL03-P1 implementation is already merged** ([contract](tl03-p1.md)), but a real macOS/Xcode/Godot ZIP export has **not** been observed and iOS remains deferred. When iOS is explicitly reprioritized with Apple Team identity and macOS/Xcode prerequisites available, verify that actual native ZIP/provenance first. Only then may TL03-P2 simulator/physical-device replay and P3 cross-target parity proceed. The current active slice is [TL04 Adapter SDK](tl04-p0.md).
