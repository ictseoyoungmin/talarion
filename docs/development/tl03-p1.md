# TL03-P1 — iOS Xcode Project Export Adapter

## Boundary

Export the **same** Godot sample and canonical replay to an iOS Xcode project archive on a qualified Mac. P1 validates a Godot-produced Xcode project ZIP. It does not compile an iOS app using Xcode, perform code signing or run a simulator/device. No Linux CI result is interpreted as iOS runtime proof.

## Supported host and prerequisites

- **macOS only**, with full Xcode selected via `xcode-select`, iPhoneOS and iPhoneSimulator SDKs installed.
- Working Godot editor with matching **iOS export templates** installed; the P0 preflight deliberately cannot prove template availability, so an actual Godot export is the authority.
- A genuine nonsecret 10-character Apple Team ID must be supplied in both `talarion.config.json` (`ios.appStoreTeamId`) and `examples/ruins-lite/export_presets.cfg` (`application/app_store_team_id`). The `bundleIdentifier` and `application/bundle_identifier` must exactly match.
- Godot sample uses Compatibility rendering for iOS Simulator. Signing profiles, Apple keys and credentials must not enter repository configuration, telemetry or public artifacts.

## CLI

```bash
node bin/talarion.mjs ios preflight artifacts/ios/preflight.json --json
node bin/talarion.mjs ios export artifacts/build/ios --json
```

`ios export` executes `godot --headless --path <project> --export-debug iOS <output>.zip` **only if** the P0 preflight passes all nine inspectable checks, the iOS preset actually exists, and the preset's bundle/Team IDs match. It stages the same replay used for Web/Android and always cleans staged replay afterward. Output stays within `artifacts/`; project, replay, preset, destination and archive paths reject traversal/symlinks. Existing ZIPs cause an explicit failure rather than stale-evidence reuse.

For Linux, Windows, missing real Apple identity or mismatching target configuration, the command writes `ios-preflight.json` plus `ios-export.json` with `ok=false`, `status=blocked` and exits nonzero. It never bypasses macOS checks through CLI options.

## Evidence schema

`talarion.ios-export/v1` records check IDs, host class, export attempted/produced state, Godot version, canonical source replay SHA-256, archive path/size/SHA-256, number of ZIP entries and the discovered `.xcodeproj/project.pbxproj` path. ZIP index inspection rejects missing Xcode project, duplicate/unsafe entries, truncation and unsupported Zip64. This is **structural evidence only**; the archive bytes are not an independently compiled executable or proof of archive contents' semantic correctness.

All outputs explicitly set `signed=false`, `xcodeBuildVerified=false`, `simulatorRuntimeObserved=false`, `physicalDeviceRuntimeObserved=false`, `parityCertified=false` and `physicalDeviceCertified=false`. P0's `exportReady=false` also remains unchanged because it is a host preflight rather than P1 certification.

## Validation / closure

- Node tests cover missing host/prerequisites, missing iOS preset, bundle and Team mismatch, malformed/traversal/duplicate ZIP metadata, blocked CLI reports, unsafe output paths and deterministic reruns.
- Existing Linux CI retains Node 20/22/24 and **actual** Godot Web/Android 15/15 state, 3/3 visual and TL00 9/9 acceptance. No new expensive or misleading Mac job is automatically introduced.
- **P1 implementation readiness** requires those regression tests to pass.
- **P1 native export closure** additionally requires a real macOS/Xcode/installed-template invocation, an archived ZIP/report with verified hashes and an independent review. Until collected, P1 stays WIP and iOS export success is unverified.
- TL03-P2 will execute the Xcode project on simulator or physical hardware and capture replay/state/screenshot/performance evidence. P3 will extend parity checks to those **observed** runtimes.
- Screenshot timing [QA issue #4](https://github.com/ictseoyoungmin/talarion/issues/4) and physical-device [Release Certification](release-certification.md) remain independently open; visual thresholds are not relaxed.
