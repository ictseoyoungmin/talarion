# TL04-P0 — Adapter SDK Contract

## Purpose

Make Talarion's existing Godot/Web/Android integration contract explicit and stable **without implementing another engine or target**. The Adapter SDK is orchestration and evidence infrastructure, not a substitute engine, source converter or certification authority.

## Existing implementation to map

- Engine/project discovery and export: `src/adapters/godot.mjs`, `src/core/config.mjs`, `src/commands/build.mjs`
- Executable runtime runners: `src/runners/web.mjs`, `src/runners/android.mjs`
- Replay and evidence identity: `src/runtime/replay-stage.mjs`, `src/runtime/evidence.mjs`, `src/runtime/provenance.mjs`
- Portability diagnostic boundary: `src/doctor/`
- Strict comparison and decision boundary: `src/parity/`, `src/visual/`, `src/runtime/gates.mjs`

## Proposed adapter manifest contract

A versioned machine-readable descriptor shall declare:

1. **Identity:** adapter ID, engine name/version matching policy, supported target IDs and schema version.
2. **Capabilities:** explicit support for project inspection, export, runtime replay, authoritative state, screenshots and observed telemetry. Each target capability must distinguish `supported`, `unsupported` and `unknown`; no silent default.
3. **Invocation boundaries:** reproducible non-shell argument execution, configured paths, target profiles and no credentials in reports.
4. **Evidence boundaries:** canonical replay identity, target/source SHA-256 and normalized runner-result references. Static claims cannot become runtime/physical-device certification.
5. **Failure semantics:** missing binary/preset, unsupported target, malformed manifest and unverified platform dependencies are machine-readable failures or explicitly unknown, never implicit PASS.

## P0 implementation

The [Godot reference manifest](../../src/adapters/godot.manifest.json) and [validator/inspector](../../src/adapters/manifest.mjs) implement a versioned, source-only declaration contract:

```bash
node bin/talarion.mjs adapter inspect --json
node bin/talarion.mjs adapter inspect web --json
node bin/talarion.mjs adapter inspect ios --json  # nonzero, unsupported
node bin/talarion.mjs verify --json
```

`talarion.adapter-manifest/v1` binds the engine ID and configuration-recommended version policy. Web/Android explicitly declare supported entrypoints; iOS is `unsupported` within the stable SDK, despite retained experimental export code. The six capabilities are `project-inspection`, `export`, `replay`, `state`, `visual` and `performance`; each must be `supported`, `unsupported` or `unknown`. Missing/extra/contradictory declarations fail closed.

`talarion.adapter-inspection/v1` validates source module presence and configured targets/profiles. It sets `authority=static-interface-declaration`, `engineVersionObserved=false`, `runtimeObserved=false`, `parityCertified=false`, `hardwareCertified=false`. It never executes a runner or claims hardware compatibility; actual exported CI evidence is independent. The inspection is included in `verify`.

Doctor's `portability.adapters` describes ownership of platform-specific gameplay API source. It does **not** register engine Adapter SDK implementations. New engine loading or generalized dispatch are deferred to P1/P2; this P0 manifest is a reference conformance binding, not a full plugin system.

## Required evidence

- Positive Godot Web/Android adapter manifest and compatibility fixtures.
- Deterministic failure cases: unsupported engine or target, unknown capability, missing export path, malformed identifiers and missing provenance.
- No change to 15/15 exported replay state, 3/3 visual tile-threshold captures, 9/9 TL00 acceptance or TL01/TL02 trust boundaries.
- No dependency on Apple developer account, macOS, iOS export, a new engine, physical device, or hosted paid runner.
- QA screenshot [issue #4](https://github.com/ictseoyoungmin/talarion/issues/4) remains an independent evidence review, not a reason to loosen gates.

## P0 exit criteria

A reviewed adapter schema, focused schema/conformance tests, stable negative diagnostics and a minimally documented Godot reference binding. Large adapter rewrites and additional runtime targets belong to later slices.
