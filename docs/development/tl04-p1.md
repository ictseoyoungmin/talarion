# TL04-P1 — Godot Adapter Dispatch Conformance

## Purpose

Connect the versioned, audited P0 Godot reference manifest to the **actual** Web/Android build and runtime commands. Use a narrow, code-reviewed implementation allowlist. An arbitrary manifest string must not become executable module authority.

## Invocation path

```text
talarion build/test <web|android>
    ↓
resolveAdapterExecution(config, target)
    ↓
inspectAdapterCommand (P0 manifest + config + repo-contained entrypoints)
    ↓
compare exactly with built-in Godot implementation registry
    ├─ web → exportGodot → runWeb (on test)
    └─ android → exportGodot → runAndroid (on test)
    ↓
existing runner evidence → existing state/visual/performance gates (unchanged)
```

Implementation: `src/adapters/dispatch.mjs`, `src/commands/build.mjs`, `src/commands/test-target.mjs`.

### Contract and evidence boundary

- `talarion.adapter-dispatch/v1` is a machine-readable per-target **source binding** with `status=bound|blocked`, `AD001–AD004` checks and the source-only P0 inspection nested under `inspection`.
- `bound` means a validated, existing implementation binding, not evidence that a tool was launched; the report always sets `runtimeObserved=false`, `parityCertified=false`, `hardwareCertified=false`.
- Runtime Web/Android verdicts continue to come exclusively from exported Godot execution, `talarion.runner-result/v1`, replay provenance and independent TL00/visual/budget gates.
- All user-configurable target/module declarations must match the **explicit** compiled registry; never dynamically import a path supplied by a project. No fallback to Godot for an unknown engine or target.
- Unsupported/deferred iOS remains outside the stable Web/Android adapter dispatch. The optional `talarion ios preflight/export` diagnostics are unaffected.

## Validation

`test/adapter-dispatch.test.mjs` asserts concrete handler identity, fail-closed iOS/unknown/Unity targets, tampered supported module paths, unsupported capability and bad profile rejection without runtime invocation. An exact-head PR CI must prove Node 20/22/24 and **real exported Web↔Android parity**, including 15/15 state, 3/3 spatial visual (2% regional tile limit) and TL00 9/9.

## Deferred

An actual third-party engine/plugin registry, independent module signing, composable driver SDKs and new target implementations are deliberately excluded until P2 and separate evidence-supported expansion.
