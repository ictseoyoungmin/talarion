# TL04-P2 — Candidate Adapter Conformance

Coding agents and contributors can inspect candidate manifests without registering or executing untrusted plugins.

## Read-only validation

```bash
node bin/talarion.mjs adapter validate src/adapters/godot.manifest.json --json
node bin/talarion.mjs adapter validate fixtures/adapters/unsafe-runner.json --json
node bin/talarion.mjs adapter validate fixtures/adapters/unsupported-engine.json --json
node bin/talarion.mjs adapter validate fixtures/adapters/malformed.json --json
```

The first is a valid source declaration. Three negative examples fail nonzero with `AM013` (unsafe module), `AM003` (unsupported engine) and `AC004` (malformed JSON). Unlike `adapter inspect`, this command accepts a candidate path but never installs it.

Candidate files must be repository-relative, symlink-free JSON files at most 256 KiB. `AC001–AC004` cover path, missing/symlink, size and syntax errors. A report includes the repository-relative source and SHA-256 digest; no content or credentials are copied to evidence. Parsed manifests undergo the existing P0 `AM001–AM030` checks for engine, supported targets, six-capability matrix, profiles and safe source entrypoints.

`authority=static-candidate-declaration` and `runtimeObserved=false`, `parityCertified=false`, `hardwareCertified=false` are invariant. Passing this audit **never** changes [P1's execution allowlist](../../src/adapters/dispatch.mjs). A new engine or target requires reviewed export/runner source, actual exported replay, state and visual evidence, provenance and independent certification where relevant. No iOS, new engine, dynamic plugin loader or physical-device certification is included here.

Run `npm test` and full exported Web↔Android CI before accepting contract changes.
