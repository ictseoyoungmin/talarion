# TL05-P0 — Independent Godot Project Adoption Audit

## Scope

A separate Godot game must be able to **meet integration prerequisites** without rewriting Talarion internals. This slice adds a **read-only static inspection** and maps sample coupling. It does **not** prove independent game execution, generate project files, modify an external repository or certify Android hardware.

## Inspect the current configured project

~~~bash
node bin/talarion.mjs project inspect --json
~~~

The command examines `talarion.config.json` and the configured project folder. `talarion.project-adoption/v1` reports `static-prerequisites-detected` or `blocked`, with stable `TA001–TA012` checks and `TA-L01–L04` unverified limitations. Any static PASS retains `runtimeObserved=false`, `independentProjectVerified=false`, `parityCertified=false` and `hardwareCertified=false`.

## Minimum adoption contract

- Place a Godot project **inside the Talarion checkout** in its own directory. An arbitrary external checkout or configurable `--config` is **not** supported yet.
- In `talarion.config.json`, change `project.path`, `project.name`, the replay source, target export presets/outputs and Android package identity to match the game.
- Add an integrated `talarion_bridge.gd` at the Godot project root and its `TalarionBridge="*res://talarion_bridge.gd"` autoload. Its `REPLAY_PATH` must equal `res://` plus `replay.stagedResource`. This checks source declaration, **not gameplay bindings**.
- The Godot `run/main_scene` must identify an existing `res://` scene inside the project. Engine identity must remain Godot.
- Godot `export_presets.cfg` must have unique named Web/Android presets with matching platforms. Their `include_filter` must match the staged JSON resource, including cases where Godot would otherwise exclude a JSON file. For Android, `package/unique_name` must match `targets.android.package`.
- Target build outputs must stay within checkout and outside the game source; source replay JSON must be readable and tick-ordered.
- Run `project inspect` and `adapter inspect` before invoking build/test. No files are created or changed by inspection.

## Current hard couplings

| Evidence or entrypoint | Limitation |
|---|---|
| `src/commands/verify.mjs` | Uses bundled `fixtures/state/web.jsonl` and `fixtures/state/android.jsonl`. Its fixture comparison is **not evidence** for another project |
| `.github/workflows/ci.yml` | Exports only Ruins Lite from the checked-in reference config |
| `src/runners/web.mjs`, `src/runners/android.mjs` | Fixed `artifacts/run/web` and `artifacts/run/android` output paths can overwrite earlier test data |
| `examples/ruins-lite/main.gd` and `talarion_bridge.gd` | Game-specific action dispatch, authoritative state, frame capture and performance markers need a new game's own integration |
| `src/core/config.mjs` | Searches upward for the single `talarion.config.json`. No independent project CLI argument or config search path yet |
| `src/adapters/manifest.mjs` | The reference adapter's executable binding is anchored to the Talarion repository; source-only declaration is not evidence of a second game |

## P0 non-goals and next proof

- The inspector does not load Godot, run export, install Android APKs, render screenshot checkpoints or validate a real game's game-state semantics.
- P1 must use a **genuinely different Godot game** and show real exported Web/Android runs, reproducible replay, state and spatial visual evidence before calling the project adoptable.
- P2 may then make the proven onboarding path safer and easier, including explicit project configuration and isolated artifacts. Do not generalize from a single sample or claim an unsupported engine/iOS target.
- Keep 15/15 state, 3/3 strict visual with 2% tile limit and TL00 9/9 acceptance of Ruins Lite unchanged.
