# WF01-P0 — Original Web-native Three.js game and browser evidence

## Implemented slice

- **Game:** `examples/web-native`, an original browser-only Signal Garden 3D collection game authored in Three.js (`three@0.180.0`, installed locally with npm), without Godot scene conversion.
- **Authoritative state:** `simulation.mjs` runs both human movement and recorded semantic movement; fixed 60 Hz replay is opt-in through `?talarionReplay=1`. A browser presentation camera is not a second game-state authority.
- **Read-only preflight:** `talarion web-native inspect [project-directory] --json` emits `talarion.web-native-inspection/v1`, with source path, symlink, schema, requirement and canonical replay tests (`WN001–WN007`). Static PASS cannot claim the game was executed.
- **Interactive development:** `talarion web-native dev [project-directory]` opens a loopback server. The browser displays a freely playable game using WASD/arrow keys and touch controls. Refresh after code edits; no hot-module replacement claimed.
- **Observed browser run:** `talarion web-native test [project-directory] --json` opens real Chromium, replays the game and records named PNG checkpoints, authoritative JSONL state, performance samples and a versioned `talarion.web-native-evidence/v1` report.
- **Provenance:** project source-file SHA-256 roster, replay SHA-256 and vendored Three.js SHA/version are captured; evidence belongs to the selected game, never `fixtures/state/`.
- **Isolation:** a project-specific temporary evidence directory avoids clobbering the Godot reference results. The file server serves only the manifest-listed assets and pinned local Three.js module; arbitrary paths are inaccessible.
- **CI:** new independent Web-native Chromium replay job, additive to the unchanged Godot Web, Godot Android and parity jobs, and Node 20/22/24.

## Run locally

~~~bash
npm install
npx playwright install chromium
node bin/talarion.mjs web-native inspect examples/web-native --json
node bin/talarion.mjs web-native dev examples/web-native
~~~

Open the loopback URL in a browser and use WASD or arrow keys to move, collecting all three beacons. Ctrl+C stops the server. For automated browser evidence in a separate terminal:

~~~bash
node bin/talarion.mjs web-native test examples/web-native --json
~~~

The default project may be omitted. The `dev` command intentionally serves until interrupted. The game HTML references an explicit pinned runtime module at `/__talarion/three.module.js`; deployment packaging must include that source locally and preserve its URL contract.

## Proven and unproven

WF01-P0 proves only **browser-native gameplay and Chromium observation** once the actual new CI job is green and its evidence is inspected. Existing Godot TL00 runtime/parity gates provide independent regression proof for the old adapter, **not** cross-engine parity.

The following remain **not implemented/certified**: arbitrary Babylon.js/Three.js project discovery beyond the constrained opt-in manifest, production-grade HMR/editor, dynamic plugin imports, Android WebView Debug APK, release AAB, Google Play readiness/publication, physical Android device performance, cross-engine shared behavior or a universal IR.
