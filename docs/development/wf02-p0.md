# WF02-P0 — Web-native Game to Android WebView Debug APK (CLOSED)

## Architecture

Signal Garden's original `examples/web-native` files and the pinned `three@0.180.0` JavaScript modules are packaged as offline APK assets. Android Java hosts the game in WebView; it does not copy or reimplement gameplay and it exports no native `addJavascriptInterface` bridge. All game resources use the isolated virtual origin `https://appassets.androidplatform.net`. External navigation and unknown asset requests are rejected. No INTERNET permission is requested, and file/content access, mixed content and popups are disabled.

Interactive launch and test Replay load the **same APK Activity**. The tester uses explicit `talarion_replay` intent flag, captures actual Android logcat state events and screen PNGs, and never substitutes fixture states. Local debug keystore remains under the developer's private Android configuration, not version-controlled or uploaded.

## Linux/macOS Debug APK workflow

~~~bash
npm install
node bin/talarion.mjs web-native android plan examples/web-native --json
node bin/talarion.mjs web-native android build examples/web-native --json
node bin/talarion.mjs web-native android test examples/web-native --json
~~~

Prerequisites: Java 17+, Android SDK Platform 35, Build Tools 35.0.1 and ADB emulator/device. Windows currently requires WSL or a supported Linux build environment; no native Windows support is certified in WF02.

The builder stages the allowlisted Web source **without changing the original project**, compiles the Android Activity with `javac`, creates DEX with `d8`, assembles resources with `aapt2` and `jar`, then `zipalign` and `apksigner`-verifies the Debug APK. No Gradle/AndroidX dependency is required by this reference host.

## Validation

- `WA001–WA003`: source + toolchain static preflight.
- `WP001–WP007`: independently observed browser and WebView runtime identities, exact game source/vendor/replay hashes, authoritative state equality, named screenshot checkpoint/tick identities, nonempty actual PNGs, terminal gameplay state, and a fixture-specific image-pixel assertion that the original Signal Garden Android HUD progression shows 1/2/3 segments at each named checkpoint.
- The Android Debug APK hash, SDK/API/build identity and signing-mode provenance are saved separately from runtime observation.
- Android screenshot presence does **not** prove exact visual similarity; WebView and desktop browser aspect ratios differ. Inspect the archived actual screenshots separately before visual acceptance.
- Godot Web/Android regression CI remains independent and unchanged.

This is an actual installable **WebView APK**, not a Godot-native translation, physical hardware certification or an AAB/Play release. WF03 handles Release AAB and Google Play preflight.

The Signal Garden HUD-area assertion is specific to this reference design and fixed emulator setup. It **does not** claim general visual or pixel equivalence, but catches screenshots that lag the authoritative state. Android `WebView.postVisualStateCallback` plus game-side replay capture hold prevent reporting stale compositor frames as verified checkpoints.
