# WF02-P1 — Installed Android Game Touch and Lifecycle QA

## Purpose and independent authority

WF02-P0 validates automated browser/WebView Replay and same-source state Parity; it cannot demonstrate real user interaction or HOME/background/resume behavior. WF02-P1 is an *independent interactive run of the very same Debug APK* against an Android emulator (or explicitly selected device). No Godot or source translation is involved.

The Android Activity never owns game state and contains no JavaScript/native game-state bridge. The original Three.js game logs each actual button click's trusted browser event, requested direction, accepted action and the authoritative game snapshot. The Activity separately logs `onPause` and `onResume` lifecycle events. The runner reads the installed app's Android logcat, never directly calls `move()` or fabricates a final state.

## Execution

With Android emulator running and WF02-P0 `test` successfully finished:

~~~bash
node bin/talarion.mjs web-native android test examples/web-native --json
node bin/talarion.mjs web-native android smoke examples/web-native --json
~~~

`smoke` requires the **existing** local `artifacts/build/android-webview/signal-garden-debug.apk`, `build-evidence.json` and the exact current original Web-source, vendor and Android host hashes; it refuses stale builds rather than quietly rebuilding the APK. It reinstalls that exact debug package.

It then launches interactive (not Replay) mode, receives the game's ready signal, taps Right twice to collect beacon 1, presses Android HOME, observes Activity pause and the system launcher, resumes the same Activity and taps Down once. The post-resume game must retain the earlier collection and position, and `INTERACTIVE_READY` must not be emitted a second time. Raw screenshots are saved at start, after collection, HOME, resumed and after the third tap.

## Acceptance and limits

- `WI000–WI015` verify source/build/package identity, trusted touch events, actual changed positions and beacon counter, device landscape orientation, lifecycle pause/resume, absence of a hidden reloaded game and five distinct raw PNG captures.
- Each screenshot and action is linked to the exact APK SHA-256 and original source hash; failing runs preserve their partial screenshot/evidence report. Separate original WF02-P0 `WP001–WP007` and legacy TL00 strict 15/15 state, 3/3 visual, TL00 9/9 must remain green.
- This is an **Android emulator interaction smoke test**, not human usability or real-hardware input-latency/thermals certification. Orientation change, external controller input, process death, persistent savegame and permission-heavy gameplay require separate coverage.
- Debug APK only; `Release AAB`, Google Play readiness, physical-device certification and any native GPU renderer conversion remain unimplemented or unverified.

The Android emulator smoke is included in the **existing** WebView emulator CI job; it deliberately does not start a second expensive Android emulator.
