# WF03-P0 — Signed Release AAB and Independent Bundle Validation

Status: **implementation candidate / CI verification required**. This feature is independent of WF01 browser runtime, WF02 offline Android WebView Debug APK and legacy Godot Web/Android.

## Scope and trust boundary

The original inspected Signal Garden Three.js assets are packaged unchanged inside the same first-party Java WebView host. The build assembles a protobuf base module (Android API 36, aapt2 --proto-format), converts it to an Android App Bundle with **bundletool 1.18.3**, signs the AAB with user-owned **external upload credentials** using jarsigner, validates its manifest, package, signature and module contents, and compares current source/vendor/host hashes against build evidence.

- Android **mobile new apps/updates** submitted since **2026-08-31** need target API **36+**, per [Google Play policy](https://support.google.com/googleplay/android-developer/answer/11926878). The reviewed, expiry-guarded policy snapshot lives at [google-play-2026-08-31.json](policies/google-play-2026-08-31.json). Recheck the official policy before submitting.
- Debug APK remains pinned to its previously observed API 35 flow. The release AAB uses a separate API 36 SDK and build-tools 36.0.0; there is no silent Debug-to-Release conversion.
- Signature inputs are supplied as four environment variables pointing to **regular files outside the repository** and a restricted alias. No keystore, password or signing material is created, committed, displayed or uploaded by the release command.
- CI uses only a short-lived disposable key **not valid as a production upload credential**. CI uploads the machine-readable gate report, not the signing key or the AAB.
- Android 64-bit ABI verification is conditional on the presence of native .so files. This current Java-only WebView host has none; Android system WebView's ABI belongs to the system image, not the AAB.
- releaseCertified, playApproved and hardwareCertified remain **false** regardless of local build success. Upload-key custody, Android package ownership, version-code monotonicity, data safety, content rating, signing enrollment, Play review and production device evidence still require separate authority.

## Requirements

Install Java 17+, Node 20+, Three.js version from package.json, Android SDK **platforms;android-36** and **build-tools;36.0.0**, zip, unzip, javac, keytool, and [bundletool-all-1.18.3.jar](https://github.com/google/bundletool/releases/tag/1.18.3), pinned SHA-256:

a099cfa1543f55593bc2ed16a70a7c67fe54b1747bb7301f37fdfd6d91028e29

Set ANDROID_SDK_ROOT, TALARION_BUNDLETOOL_JAR, TALARION_RELEASE_KEYSTORE, TALARION_RELEASE_ALIAS, TALARION_RELEASE_STOREPASS_FILE, and TALARION_RELEASE_KEYPASS_FILE. Pass files containing secrets via *_FILE, not inline passwords in command-line arguments or GitHub repository secrets printed in logs.

## Agent and local workflow

~~~bash
node bin/talarion.mjs web-native android release plan examples/web-native --json
node bin/talarion.mjs web-native android release build examples/web-native --json
node bin/talarion.mjs web-native android release verify examples/web-native --json
# Requires explicitly selected/authorized Android emulator/device.
node bin/talarion.mjs web-native android release test examples/web-native --json
~~~

Artifacts live under ignored artifacts/build/android-webview-release/: signed .aab, release-evidence JSON; optional .apks, extracted APK, and install-evidence JSON after test. verify re-checks AAB contents, signature and source provenance without a device. test uses bundletool build-apks --mode=universal to create a separately signed APK and installs/launches it over ADB. This does not prove full gameplay parity, process-death persistence, physical-device compatibility or Google Play approval.

## Evidence and completion boundaries

WR001–WR010 gate environment, external secrets, pinned source and policy. build requires all checks before compilation. verify independently recalculates evidence, signature and source identity. AAB ZIP must include base/manifest/AndroidManifest.xml, base/dex/classes.dex, and game assets. Native 32-bit libraries without matching 64-bit counterparts are rejected.

For P0 acceptance: real CI must complete Node 20/22/24 checks, unchanged WF01/WF02/Godot evidence and the new API 36 AAB build+validate job at the exact PR head. A user-owned upload key and independently installed release APK can later support a stronger **WF03-P1** gate, but neither is inferred from CI's disposable signer. Never mark Google Play certification or store publication complete merely because a local AAB was generated.
