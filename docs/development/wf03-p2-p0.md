# WF03-P2-0 — Google Play Static Submission Contract

**Scope:** implemented reference CLI for read-only policy and metadata validation. It is **not** a production upload signer, Android bundle inspector, Play Console connector, store acceptance gate or physical-device certificate.

## Interface

```bash
node bin/talarion.mjs play preflight examples/play-submission.mobile.json --json
node bin/talarion.mjs play preflight examples/play-submission.mobile.json artifacts/play/preflight.json --json
```

The contract is game-neutral and engine-neutral: `schema`, `platform`, `submission`, `application`, `artifact` and `declarations`. No Godot/Three.js imports or game-specific package constants appear in the auditor. The bundled demonstration declares `dev.talarion.signalgarden` but **does not establish real Play application ownership**.

Twelve `PC001–PC012` checks validate exact contract schema, Android package syntax, bounded versionCode/versionName, freshness of the pinned official Google Play target API policy, category-scoped mobile submission API36, min SDK, increasing versionCode for updates, AAB identity and declared signer class, permissions inventory, eight declaration statuses, prohibition on secrets or self-issued approval booleans, and unknown-field rejection.

The snapshot source is [official Google Play target API policy](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en) (mobile new apps and updates API36 from 2026-08-31). A 90-day review freshness gate is not a live policy verification. Android TV, XR, Wear OS and Automotive are **explicitly unsupported** by this mobile contract rather than silently using mobile thresholds or inventing an exemption.

`ok:true` means **static contract shape passed only**, not store eligibility. Every successful result still sets `status:"blocked-by-external-account"`, `submissionReady:false`, `playApproved:false`, `playPublished:false`, `productionSigningVerified:false`, `physicalDeviceCertified:false`. Five `PE001–PE005` external actions require actual Play Console developer/account identity, package ownership, prior version history, Play App Signing/upload key, privacy/data safety/ads/rating/audience/listing verification and independently accepted publication. Disposable CI signing adds `PE006`. All eight declarations are separately tracked, with missing statuses rejected. Even `owner-reviewed` is **only a user declaration**, not verified Play Console evidence.

**Evidence authority:** The JSON contract cannot cryptographically prove package ownership or app contents. P2-0 performs no secret reading, AAB upload, bundle generation, Play Console access, publishing or network lookups. P0/P1 separately inspect signed AAB and actually run the extracted Release APK. P2-1 must bind *that real artifact* and its signer to externally attested Play Console account evidence before a stronger verdict can be produced.

## Security and QA

- Secret-bearing fields (passwords, keystores, private keys, token strings) and input flags claiming `playApproved`, `playReady` or `releaseCertified` are prohibited; do not accept user self-certification.
- The policy snapshot is pinned, effective-date checked, reviewed within 90 days and official-domain URL checked. Policies must be checked against Google again before actual submission.
- Update versionCode is checked against an **explicitly declared previous number**; the real Play Console maximum remains externally unverified. Missing historic version is rejected.
- Structured JSON output is intentionally noncertifying even when static checks pass.
- CI runs independent fixture and negative tests on Node 20, 22, and 24, and also publishes a machine-readable static preflight report. P2-1 production signer and P2-2 real-device/store verification remain open.

*Important:* A Play publisher must review the platform's full current policies and obtain Play Console confirmation. This local check is not legal or platform compliance certification.
